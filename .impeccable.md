## Design Context

### Users

Keyboard-first HEY customers using a native desktop client to triage mail, read conversations, compose replies, and work with a local Pi agent without leaving their mail flow.

### Brand Personality

Calm, familiar, and precise. The interface should feel capable and personal, with HEY-native language and structure rather than generic productivity-app chrome.

### Aesthetic Direction

Refined minimalism that preserves the app's Omarchy-aware look and feel while borrowing HEY's information architecture and interaction clarity. Support the active system theme. Avoid excessive borders, boxes, shields, decorative cards, redundant actions, and dense table-style mail layouts.

### Design Principles

- Prefer HEY's established concepts, language, and structural placement when the capability is native to HEY.
- Keep one clear action at the point of use; move destructive or uncommon actions into progressive disclosure.
- Treat keyboard navigation as a complete interaction model, not an accessory to pointer controls.
- Preserve reading space: mail owns the primary pane and the agent owns the independent right rail.
- Use restrained spacing, typography, borders, and motion so content remains the visual focus.
